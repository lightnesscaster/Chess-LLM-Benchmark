# Benchmark seed uncertainty audit, 2026-10-14

Decision: retain the global benchmark starting RD of **166**. RD300 is a promising research candidate, but this audit does not establish a reliable improvement outside Argon. No production rating settings, player ratings, or saved games were changed.

## Evidence and metrics

The candidate grid was fixed at 166, 250, 300, 350 before computing metrics. Lower squared expected-score error (Brier) is better. Macro averages give each model family equal weight. These forecasts predict expected score, not a three-way win/draw/loss distribution.

The primary cohort uses seven benchmark predictions whose shadow-registry records were locked with zero recorded games. It contains **57 distinct games, 67 player forecasts, four families, and two laboratories**. Ten games involve two cohort players and contribute two correlated forecasts. It is not a sample of 67 independent games. Excluding Argon leaves 48 games / 58 forecasts / three families; its first-ten-game subset contains 27 games / 34 forecasts.

This does not support selecting a new global default from this cohort.

They cannot establish the optimal RD: the historical benchmark artifacts lack acquisition timestamps, and the rating predictor was fitted using game-derived ratings. Conditioning on today's benchmark means can therefore leak information unavailable at historical forecast time. These numbers are explicitly retrospective, not fully held-out validation.

## Replay contract and limitations

- Each player's score is forecast before applying the current result. Both players update from the same prior state with the existing stationary Glicko implementation. There is one chronological pass, no anchor-first rearrangement and no later-pass sibling snapshots.
- **Order is by completion time.** `GameResult.created_at` is recorded when the result is constructed, and the schema lacks start timestamps. Earlier completed games can have finished while another game was already running. Concrete overlap exists in the primary cohort. Thus this is a completion-order, result-held-out audit; it does not reconstruct actual start-time forecasts. Strict start-time forecasting would require additional historical data or newly recorded start snapshots.
- Primary seed means come from locked shadow entries, with zero-game eligibility checked and locks required to precede the player's first recorded result. This verifies recorded-result ordering, not undocumented game-start ordering. Other primary-run opponents are learned chronologically without position-benchmark seeds; historical anchor values and each human opponent's fixed rated-game snapshot are preserved. This conservative benchmark-free opponent reconstruction differs from actual production state and adds uncertainty.
- Higher-effort models may inherit the rating of a previously encountered lower-effort sibling, matching production's seed rule without future sibling information. Candidate RD changes affect both learning and these causal sibling seeds.
- The forecast uses production's expected-score formula with opponent RD. Two sides of a model-versus-model game need not produce complementary expected scores. They are scored separately and their dependence is acknowledged.
- Ghost opponents do not update or contribute scored forecasts for the other player. Human accounts never enter the rated pool. No final-rating or future legality-rate features are used.
- Excluding Argon removes its scored forecasts, not the matches from the contextual replay. This is a sensitivity analysis, not untouched confirmation: Argon's known performance motivated the experiment.
- Family macro weighting reduces domination by high-volume models, but families are connected through opponents and only two labs appear in the primary cohort. No independence-based significance claim or precise confidence interval is justified.
- This evaluator is intentionally different from the production multi-pass recalculation. Its final replay ratings are diagnostics, not a proposed production migration.

The snapshot manifest hashes the results, engine configuration, model metadata, benchmark panels, benchmark results and shadow locks. The evaluator requires the complete expected manifest and rejects altered inputs. The private `report.json` also records hashes of the evaluator, CLI, predictor, Glicko implementation, anchor resolver, effort-seeding logic and release-family grouping. Reproduction requires those matching implementation versions; input hashes alone do not pin the algorithms.

```bash
# First run only, after placing the read-only production result export here:
.venv/bin/python scripts/backtest_seed_rd.py \
  --snapshot-dir data/seed_rd_backtest_20261014 --freeze

# Rerun against the same verified frozen inputs:
.venv/bin/python scripts/backtest_seed_rd.py \
  --snapshot-dir data/seed_rd_backtest_20261014

.venv/bin/python -m pytest \
  tests/test_seed_rd_backtest.py tests/test_backtest_seed_rd_script.py \
  tests/test_anchor_history.py tests/test_rating_recalculation.py \
  tests/test_rating_cache.py -q
```

Tests cover prefix invariance, pre-result scoring, simultaneous updates, seed availability, past-only sibling inheritance, dated anchors, fixed human snapshots, ghost rules, duplicate/invalid outcomes, draw scores, production expected-score calculations, family weighting, cohort eligibility and snapshot integrity. Independent review identified the completion-time limitation and requested code-provenance hashes and complete-manifest validation; these were addressed.

No new model calls, match publications, production rating writes, or deployment were needed for this audit.
